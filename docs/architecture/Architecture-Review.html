Why are TLS and DNSSEC both needed?

TLS authenticates the gateway and encrypts the client connection. DNSSEC validates the DNS records at Unbound. The ESP32 relies on the authenticated gateway's result; it does not validate the full DNSSEC chain itself.

What does this prototype actually demonstrate?

A physical ESP32 connects through Windows forwarding to Unbound inside WSL. BIND serves controlled local test zones. The local trust anchor is not a public-root DNS chain. TLS authenticates the server only. There is no Docker deployment or production service implied by these diagrams.

How should rejected responses be interpreted?

Unsigned is not automatically malicious: our strict policy blocks it. SERVFAIL alone does not establish a signature failure without matching gateway logs. NXDOMAIN can be an authenticated negative answer. None of these cases supplies a usable destination to the client.
